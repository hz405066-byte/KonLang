# KonLang

Интерпретатор и компилятор языка **KonLang** (редакция 5 «Curses», версия инструмента 1.1.0).

Проект умеет выполнять программу двумя способами:

1. **Древовидный интерпретатор** — разбор исходника и обход AST.
2. **Компилятор + виртуальная машина** — исходник превращается в байт-код, который можно
   сохранить в переносимый образ `.knc`, выполнить встроенной ВМ или встроить в автономный
   исполняемый файл текущей платформы.

Обе ветки используют одни и те же значения, экран и файловые операции, поэтому дают
одинаковый результат. Это проверяется эталонными тестами на всех примерах.

## Быстрый старт

```bash
cd konlang
go build -o konlang ./cmd/konlang

./konlang run examples/hello.kn          # интерпретатор
./konlang run --vm examples/fact.kn      # компиляция и выполнение в ВМ
./konlang build examples/hello.kn        # автономный бинарник examples/hello
./konlang build -target bc -o hello.knc examples/hello.kn
./konlang run hello.knc                  # запуск готового образа
./konlang disasm hello.knc               # дизассемблер
```

Требуется Go 1.21 или новее.

## Команды

| Команда | Назначение |
|---|---|
| `konlang run [флаги] file.kn` | выполнить исходник интерпретатором |
| `konlang run --vm [флаги] file.kn` | скомпилировать и выполнить в байт-код-ВМ |
| `konlang run [флаги] file.knc` | выполнить готовый образ байт-кода |
| `konlang vm file.knc` | то же, что `run file.knc` |
| `konlang file.kn` | короткая форма `run` |
| `konlang build [флаги] file.kn` | собрать автономный бинарник или образ `.knc` |
| `konlang disasm file.knc` | показать дизассемблер образа |
| `konlang check file...` | проверить синтаксис, компиляцию и целостность `.knc` |
| `konlang ast file.kn` | вывести дерево разбора |
| `konlang tokens file.kn` | вывести токены лексера |
| `konlang repl` | интерактивная оболочка |
| `konlang version` | версия |

Флаги `run`:

| Флаг | Значение |
|---|---|
| `--vm` | выполнять не AST, а скомпилированный байт-код |
| `--screen` | буферный экран даже без TTY; кадр печатается при завершении |
| `--width N`, `--height N` | размер экрана (по умолчанию размер терминала или 80×25) |
| `--seed N` | зерно ГПСЧ для воспроизводимости |
| `--trace` | трассировка конструкций/опкодов в `stderr` |

### Сборка

```bash
konlang build [-target native|bc|dos|pros] [-o файл] [--emit-bc] [--emit-asm] file.kn
```

| Цель | Результат | Кодировка | Примечание |
|---|---|---|---|
| `native` (по умолчанию) | исполняемый файл текущей ОС | UTF-8 | копия `konlang` со встроенным образом и ВМ |
| `bc` | переносимый образ `.knc` | UTF-8 | запускается `konlang run file.knc` |
| `dos` | образ `.knc` с метаданными DOS | CP866 | пока **не** является `.COM`-файлом |
| `pros` | образ `.knc` с метаданными x16-PRos | CP866 | пока **не** является `.BIN`-файлом |

`--emit-bc` сохраняет рядом дизассемблер `<имя>.disasm.txt`.
`--emit-asm` сохраняет `<имя>.asm` — NASM-директивы `db` с байтами образа, пригодные для
встраивания в будущий 16-битный рантайм, но не готовую программу.

> **Статус DOS/ProS.** Настоящий 16-битный рантайм для MS-DOS/x16-PRos в проекте пока
> отсутствует. Цели `dos` и `pros` завершают компиляцию и упаковку: байт-код и строки
> переводятся в CP866, в заголовке образа выставляются `target=dos|pros`. Такой `.knc`
> можно выполнить встроенной хост-ВМ (она декодирует CP866 обратно в UTF-8) или передать
> внешнему/будущему 16-битному интерпретатору. Автономные `.COM`/`.BIN` не генерируются.

## Архитектура

```
исходник .kn
    │
    ├─ internal/lexer ──► токены
    ├─ internal/parser ─► AST (internal/ast)
    │
    ├─ internal/interp ─► выполнение AST
    │
    └─ internal/compiler ─► байт-код + пул констант + имена
                                │
                                ├─ image.go ─► .knc (KNBC + CRC32)
                                └─ internal/vm ─► выполнение
```

| Пакет | Роль |
|---|---|
| `internal/lexer` | лексер, позиции, строковые литералы |
| `internal/parser` | рекурсивный разбор языка в AST |
| `internal/ast` | узлы дерева и дамп |
| `internal/interp` | древовидный интерпретатор |
| `internal/compiler` | генерация байт-кода, опкоды, кодировки, образ `.knc` |
| `internal/vm` | стековая ВМ, области видимости, `exec`, файлы, ввод |
| `internal/value` | значения: int, float, string, list, nil, code |
| `internal/term` | TTY, построчный и буферный экран, клавиши, цвета |
| `cmd/konlang` | CLI и встраивание образа в автономный бинарник |
| `tests` | эталонные тесты, паритет интерпретатора и ВМ, CLI-интеграция |

### Поток компиляции

1. Парсер строит AST.
2. `compiler.CompileWith` обходит узлы и генерирует стековый байт-код.
3. `inp[имя]` подключает `имя.kn` рядом с исходником (или встроенный `style_text`) на этапе
   компиляции; библиотека встраивается в образ, рекурсивный импорт запрещён.
4. Константы дедуплицируются, имена складываются в NUL-терминированный пул.
5. `Program.Marshal` добавляет заголовок `KNBC`, длины секций и CRC32.
6. `Unmarshal` проверяет сигнатуру, версию, размеры, CRC32 и заново строит таблицы
   констант/имён для дизассемблера и ВМ.

### Байт-код

Стековая машина с 16-битными операндами. Основные группы команд:

- стек и константы: `PUSHK`, `PUSHNIL`, `POP`, `DUP`;
- переменные: `LOAD`, `STORE`, `LOADREG` (регистры `inp_`, `rand_`, `key_`, `kon_`, `scr_`, `cur_`);
- списки и индексы: `MKLIST`, `INDEX`, `LEN`;
- арифметика, сравнения, логика, `CONCAT`, `REPEAT`, `CAST`;
- переходы и вызовы: `JMP`, `JZ`, `JNZ`, `CALL`, `KON`, `DEF`, `RETV`, `RETN`;
- ввод/вывод и терминал: `PRINT`, `PRINTXY`, `INPUT`, `KEY`, `CLEAR`, `SCRSIZE`, `SCRCUR`, `SCRBG`, `BEEP`, `STYLE`;
- библиотеки и файлы: `IMPORT`, `FOPEN`, `FWRITE`, `FAPPEND`, `FDEL`, `FLIST`;
- `TIME`, `EXIT`, `RANDOM`, `EXEC`, `HALT`.

Полный список с кодами — в `internal/compiler/opcodes.go`, читаемый дамп — `konlang disasm`.

### Формат образа `.knc`

Заголовок 24 байта, little-endian:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 4 | сигнатура `KNBC` |
| 4 | 1 | версия, сейчас `1` |
| 5 | 1 | кодировка: `0` UTF-8, `1` CP866 |
| 6 | 1 | цель: `0` portable, `1` dos, `2` pros |
| 7 | 1 | резерв |
| 8 | 4 | длина секции кода |
| 12 | 4 | длина пула констант |
| 16 | 4 | длина блока имён |
| 20 | 4 | CRC32 IEEE от payload |
| 24 | … | `code || consts || names` |

Пул констант: `uint16 n`, затем `n` смещений `uint16`, затем записи:

- `1` — `int32`;
- `2` — `int32`, дробное с фиксированной точкой (4 знака);
- `3` — `uint16 length` + байты строки.

Блок имён — подряд идущие NUL-терминированные строки. Ограничения: код, пул имён и пул
констант — до 65535 байт; строковая константа — до 65535 байт; индексы и адреса — 16-битные.

### Автономный бинарник

`konlang build` (цель `native`) копирует текущий исполняемый файл `konlang` и дописывает в
конец образ `.knc` и 16-байтный футер:

| Смещение от конца | Поле |
|---:|---|
| −16 | `KNLANG01` |
| −8 | `uint32` длина образа |
| −4 | `uint32` CRC32 образа |

При старте `konlang` сначала ищет футер. Если он найден и CRC верна, программа сразу
выполняет встроенный образ, не разбирая аргументы командной строки. Поэтому такой файл
можно переименовать и запускать как обычное приложение. Рабочая папка — текущая папка
запуска; трассировка включается переменной `KONLANG_TRACE=1`.

Автономный файл платформозависим: он собран для той ОС/архитектуры, для которой собран
сам `konlang`. Для другой платформы нужно пересобрать `konlang` под неё.

## Виртуальная машина

- Стек значений, кадры вызовов и область видимости функции; глобальные переменные — вне
  функций.
- Максимум 8 параметров функции, глубина рекурсии — 400.
- `exec` выполняет контейнер `kon_*` или компилирует строку как блок кода во время работы.
  Строка может вызывать функции, определённые во внешней программе, и наследует
  подключённые библиотеки (`inp[style_text]` отмечается в байт-коде командой `IMPORT`).
- Ввод типизированный: при неверном формате ВМ повторяет запрос, как интерпретатор.
- Файлы и `exec`-строки разрешаются относительно папки исходника (для `run`) или текущей
  папки (для автономного бинарника).
- `--seed` делает `random_*` воспроизводимым; `0` означает случайное зерно.
- CP866-образы декодируются при загрузке, поэтому встроенная ВМ печатает корректный UTF-8.
- `time1` или `time [n]` ждёт `n` десятых долей секунды (как в интерпретаторе).
- Строки `repeat`/`*` ограничены 100000 повторов.

## Проверка

```bash
go test ./...
go test -short ./...   # без сборки CLI в интеграционном тесте
go vet ./...
```

Тесты покрывают:

- эталонный вывод всех программ из `examples/` интерпретатором;
- тот же вывод через компилятор и ВМ;
- сохранение/загрузку `.knc`, CRC, повреждённые образы, CP866;
- `exec` контейнеров и строк, вызовы внешних функций и наследование `style_text`;
- файловые библиотеки и защиту от рекурсивного импорта;
- ошибки ВМ и неверную арность встроенных функций без паник;
- округление дробных литералов до 4 знаков;
- полный CLI-путь: `build native` → запуск бинарника → `build bc` → `run .knc` → `disasm`;
- устойчивость дизассемблера к обрезанному коду и отказ от слишком длинных констант.

## Ограничения

- Целочисленные литералы ограничены `int32`, вычисления идут в `int64`.
- Дробные литералы хранятся с фиксированной точкой (4 знака, с округлением),
  вычисления — в `float64`.
- В образе до 65535 байт кода; имена, константы и их смещения — 16-битные.
- CP866 покрывает кириллицу и псевдографику; отсутствующие в таблице символы
  заменяются на `?` при сборке образа `dos`/`pros`.
- `dos`/`pros` не создают загрузочные `.COM`/`.BIN`: нужен отдельный 16-битный рантайм.
- `--emit-asm` — только данные образа, не исполняемый файл.
- Автономный бинарник не принимает флаги `--seed`, `--screen`, `--width`, `--height`;
  доступна только трассировка через `KONLANG_TRACE`.
- TUI-возможности (цвета, позиционирование, клавиши) зависят от терминала; в
  перенаправленном выводе используется построчный режим.
